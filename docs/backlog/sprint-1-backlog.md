## 1. Sprint 目标（一句话，可演示）

> **让一个从没来过的同学，在演示现场完成「注册 → 登录 → 提问 → 在列表里看到自己的问题 → 打开详情页」，全程走 PR 评审合入 main。**

验收方式：Sprint Review 时由**非本团队的老师/同学**现场操作一遍，不念稿。

## 2. 容量与承诺

| 项目 | 数值 | 说明 |
|---|---|---|
| 团队规模 | 5 人（PO 1 / SM 1 / Dev 3） | 按 Lab 1 组建结果 |

> 承诺超额 = 用"完成率"换"可信度"，Review 时最难看。

## 5. 看板配置

| 列 | 含义 | WIP 限制 |
|---|---|---|
| To Do | 本 Sprint 已承诺、未开始 | — |
| In Progress | 有人正在写 | ≤ 5（等于团队人数） |
| In Review | 已提 PR、等评审 | ≤ 2（卡住就全队帮忙评） |
| Done | 满足 DoD 且已合入 main | — |
| Blocked | 外部阻塞（独立泳道，不占 WIP） | — |

- 卡片命名：`[US-编号] 模块-动作`，例如 `[US-04] 前端-Markdown 预览`；
- 每张卡必须挂到对应 US 的 Epic（GitHub Issue / Gitee 需求）上，便于统计完成度。

## 6. 完成的定义（DoD，全队签字确认）

一条故事只有全部满足才能进 Done：

1. 代码经 PR 合入 `main`，**至少 1 人 review 且 LGTM**，无直推；
2. 单元测试覆盖新增逻辑的关键分支，`mvn test` / `pnpm test` 全绿；
3. CI（build + test）通过；
4. 对应 `.feature` 验收标准中的**快乐路径 + 至少 1 条异常路径**手工验证通过；
5. 无新增 SonarQube/ESLint 告警（可临时豁免但需在 PR 里写明原因）；
6. 接口变更同步更新 `openapi.yaml`，前端类型重新生成；
7. 数据库变更以 Flyway 脚本提交，可在空库一键迁移；
8. 演示脚本（3 分钟能讲完的步骤）写进 PR 描述或 `docs/demo/`。
